# Vision «в поле» — инструкция для проверки на реальном экране знакомств

Это единственный оставшийся сценарий, который нельзя выполнить без человека с
реальным экраном площадки. Всё, что можно было провести машинно (API-контракт
`POST /api/v1/vision/observations`, троттлинг, retention), покрыто тестами
(`test_vision*.py`) и live-smoke фазы 2; здесь — процедура для оператора.

## Предпосылки
- Собранный клиент установлен (инсталлятор из релиза v0.1.0), бэкенд поднят
  (compose или runbook §2), в «Настройках» указан адрес API и токен.
- Локальный vision-провайдер (оффлайн-дефолт):
  `MATCH_VISION_PROVIDER=ollama` + поднятый Ollama с vision-моделью
  (`MATCH_VISION_OLLAMA_BASE_URL`, по умолчанию `http://localhost:11434`).
  Кадры уходят только в него; внешней отправки экрана нет (см.
  `docs/privacy/privacy-policy.md`).
- Важно: автоматизация действий на площадках запрещена их ToS — агент
  только наблюдает экран и предлагает решения; отправку выполняет человек
  вручную (см. `docs/release/release-notes.md`, ADR-0004/0008).

## Шаги
1. Создать диалог в клиенте (ручной импорт нескольких реплик с реального чата).
2. Включить наблюдение: на реальном экране диалога → «Vision» → выбрать
   беседу → «Наблюдать». Клиент снимает кадры и отправляет
   `POST /api/v1/vision/observations` (frame_base64 PNG + source_label).
3. Проверить троттлинг: чаще допустимого интервала наблюдение не создаётся
   ( throttle в `app.vision.service`), лишние кадры отвечают отказом, а не 500.
4. «Решения»: агент предлагает действие с обоснованием (evidence из кадров +
   истории диалога) — проверить, что предложения релевантны экрану.
5. Одобрить/отклонить предложение вручную (поток approve/reject). Отправку
   выполнить самим на площадке.
6. «Память»: наблюдения и события отображаются; эмпатия/риски в «Аналитике»
   не содержат персональных данных сверх необходимого.
7. «Приватность»: `GET /api/v1/privacy/export` → в выгрузке есть
   `vision_observations`; по запросу на удаление данные наблюдений удаляются.

## Что фиксировать по результату
- [ ] Наблюдения создаются на реальном экране (201 + связь с беседой)
- [ ] Троттлинг и ошибки кадров обрабатываются без 500
- [ ] Предложения агента релевантны (обоснование ссылается на экран/историю)
- [ ] Ручное одобрение/отклонение работает, дублей при retry нет
- [ ] Выгрузка/удаление приватности включают наблюдения
- [ ] Задержка «кадр → наблюдение» в пределах таймаута vision-провайдера

Итог отметить в `docs/release/acceptance-checklist.md` (пункт 16) одной строкой
с датой и результатом.
