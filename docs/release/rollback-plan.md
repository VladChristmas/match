# План отката (Этап 9)

Цель: безопасно вернуть систему в рабочее состояние при неудачном релизе.

## Клиент (Tauri)
1. Клиент ставится/обновляется отдельно от сервера; откат — установка предыдущей версии сборки.
2. Откат клиента не затрагивает данные сервера. Локальные настройки — `%APPDATA%/com.match.desktop/settings.json`.

## Схема БД (Alembic)
1. Определить текущую ревизию: `alembic current`.
2. Найти ревизию до релиза: `alembic history`.
3. Откат на одну ревизию: `alembic downgrade -1` (каждая миграция 0001–0006 имеет `downgrade`).
4. Если откат схемы невозможен — восстановление из резервной копии БД (ниже).

## Резервное копирование / восстановление БД
1. Дамп до релиза:
   `docker exec infra-db-1 pg_dump -U match -d match > backup_before_release.sql`
2. Восстановление:
   `docker exec -i infra-db-1 psql -U match -d match < backup_before_release.sql`

## Сервер (FastAPI)
1. Откатить образ/код до предыдущего коммита, перезапустить сервис.
2. Проверить `/health` (liveness) и `/health/ready` (готовность БД).
3. Отключить авто-отправку при инциденте: `POST /api/v1/agent/pause` (пауза очереди).

## Порядок при инциденте
1. Поставить агента на паузу (остановить исходящие действия).
2. Зафиксировать состояние (логи, текущая ревизия, дамп).
3. Откатить клиент и/или сервер и/или схему.
4. Проверить работоспособность и уведомить пользователей.
