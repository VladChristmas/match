# Release Notes — MATCH 0.1.0 (релизный кандидат)

Дата: 2026-10-25. Ветка `main`, HEAD на момент подготовки — `b37b649`.

## Что вошло после аудита релиза (этапы 27–31)

**Безопасное исполнение (этап 28, ADR-0034)**
- Бюджет автономности перепроверяется непосредственно перед каждой доставкой —
  и при авто-отправке, и при approve человека, и в воркере отложенной доставки.
  Глобальная остановка (`global_paused`) больше не обходится: approve под
  остановкой отвечает `409` с причиной, воркер пропускает доставку, не расходуя
  попытки. `queue_paused` блокирует только автономную доставку.
- Входящая переписка (импорт) — недоверенный ввод: текст обрамляется маркерами
  `<<<untrusted data>>>` с нейтрализацией маркеров внутри данных; системный
  промпт инструктирует не исполнять содержащиеся там «инструкции»; валидатор
  флагит черновики, воспроизводящие маркеры или системный промпт. Полная защита
  от jailbreak fencing не гарантируется — граница остаётся архитектурной:
  черновик никогда не исполняется автоматически (Decision Loop → бюджет → человек).

**Интеллект в интерфейсе (этап 29, ADR-0035)**
- Новые экраны клиента: «Решения» (журнал Decision Loop + оценка без побочных
  эффектов), «Динамика» (сигналы, пересчёт, сравнение периодов, поворотные
  точки), «Память» (полный жизненный цикл локальных воспоминаний), «Приватность»
  (экспорт JSON, удаление с подтверждением), расширенная «Автономность»
  (бюджет, глобальная остановка, журнал ошибок, правила калибровки).
- Надёжность сети: таймаут 20 с + abort, один автоматический повтор загрузок,
  оффлайн-очередь с лимитом 10 попыток и причиной отброса в журнал.
- Первый запуск предупреждает об отсутствии токена и ведёт в настройки.

**Проверки на боевом PostgreSQL и прод-настройки (этап 30, ADR-0036)**
- Исправлен реальный дефект: `POST /api/v1/dynamics/signals/compute` отвечал
  500 на PostgreSQL (срав naïve/aware-даты) при зелёных SQLite-тестах; добавлена
  нормализация `_as_utc` и живой smoke (`scripts/pg_smoke.py`) — и то и другое
  в CI (job `db-migrations`: PostgreSQL, alembic up→down→up, smoke).
- CI впервые зелёный целиком: `7972f16` (было: desktop-job'ы падали с первого
  релиза из-за `pnpm/action-setup` без версии).
- Прод-дефолты в `infra/docker-compose.yml`: легаси-автопровижининг выключен,
  rate-limit 60/мин (db-бэкенд), явные CORS-origin'ы, уровень логов.
- Удаление воспоминания удаляет его события одной транзакцией.
- CSP для Tauri-окна и полный набор иконок в бандле.

**Сборка релиза и документация (этап 31)**

```powershell

.\scripts\check.ps1                    # ruff, 164 pytest, pnpm build, cargo fmt/clippy/test
```

CI: `.github/workflows/ci.yml` — backend, desktop-web, desktop-rust,

## Установка и обновление

- Установщик: `apps\desktop\src-tauri\target\release\bundle\` (msi/nsis).
  Собрать: `pnpm tauri build` из `apps\desktop` (после `. .\scripts\dev-env.ps1`).
- Обновление поверх предыдущей версии: установщик заменяет приложение; локальная
  база `match.db` в каталоге данных приложения сохраняется (схема v4).
- Сервер при обновлении: `alembic upgrade head` до запуска (миграции 0001–0015).
- Настройки клиента (адрес API, токен) сохраняются в `match.db`.

## Известные ограничения (не блокируют сценарий)

- Дефолтный LLM-провайдер — `echo` (офлайн-режим): «умный» черновик требует
  настройки облачного ключа или Ollama (`MATCH_LLM_PRESET=groq|gemini|openrouter|cerebras`).
- Память агента живёт только на устройстве (OQ-10, ADR-0030); сервер хранит
  профиль, диалоги, решения и динамику.
- Активные часы бюджета автономности — UTC (пользовательских таймзон нет).
- Реальные интеграции с площадками знакомств не реализованы по дизайну
  (vision-агент + ручной импорт, ToS площадок запрещают автоматизацию).
- `MATCH_LLM_USER_REQUEST_LIMIT` по умолчанию 0 (выключен) — задать при выборе
  облачного провайдера.
