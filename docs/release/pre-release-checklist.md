# Чек-лист предрелиза (Этап 9)

Статус: черновик предрелиза. Отмечать по мере проверки.

## Безопасность
- [ ] Токен доступа хранится только локально на клиенте; не логируется (`app/api/deps.py`).
- [ ] Все маршруты `/api/v1/*` требуют токен; доступ к объектам — по владельцу (защита от IDOR).
- [ ] Входящие сообщения считаются недоверенным вводом; защита от prompt injection (валидатор диалога).
- [ ] Прямые действия модели запрещены: только через `agent-runtime`/очередь (`agent_actions`).
- [ ] Инструменты модели ограничены allowlist (ADR-0006).

## Приватность
- [ ] Психопрофиль собеседника виден только пользователю (ADR-0005).
- [ ] Персональные данные не собираются сверх созданных пользователем (ADR-0007).
- [ ] `GET /api/v1/privacy/export` отдаёт полный экспорт (`token_ref` редактируется).
- [ ] `POST /api/v1/privacy/deletion-request` удаляет все данные пользователя (проверено тестом).
- [ ] Токены площадок не хранятся и не запрашиваются (интеграции `unsupported`, ADR-0014).

## Нагрузка
- [ ] `MATCH_RATE_LIMIT_PER_MINUTE` задан для продуктивного окружения (по умолчанию 0 = выключено).
- [ ] Лимит LLM-запросов на пользователя `MATCH_LLM_USER_REQUEST_LIMIT` настроен.
- [ ] Ограничение нагрузки применяется к `/drafts` и `/agent/actions` (`429`).
- [ ] Проверена деградация при недоступности LLM: `503` и fallback-провайдеры (ADR-0013).

## Восстановление / откат
- [ ] Есть резервная копия БД (PostgreSQL) перед релизом.
- [ ] Миграции проверены вверх и вниз (`alembic upgrade head` / `downgrade`).
- [ ] Известен план отката (`docs/release/rollback-plan.md`).
- [ ] Прогон инструкции (`docs/release/runbook.md`) на чистом окружении.

## Качество
- [ ] `ruff check .` — чисто; `pytest -q` — зелёный (backend).
- [ ] `pnpm build` (клиент) — зелёный; `cargo check` — зелёный.
- [ ] CI зелёный (backend, desktop-web, desktop-rust).
