# GUI-прогон лаборатории «Эмулятор и тесты» — инструкция оператору

Статус: чек-лист для человеко-управляемого прогона (создано 2026-10-30, сессия 16).
Автоматическая часть (регламентный прогон через реальный HTTP API без GUI) —
`scripts/emulator_lab_live.py` (31/31, см. acceptance-checklist §26). Этот документ
покрывает оставшийся пункт: работу самой вкладки в приложении.

## Предпосылки

1. API поднят и доступен из клиента:
   - dev: `services\api\.venv\Scripts\python.exe -m uvicorn app.main:app` (8888/8000),
     БД — PostgreSQL 5433 (`infra-db-1`);
   - для OK-прогона сценариев нужен валидный токен: «Настройки» → адрес API
     `http://127.0.0.1:8000` + токен (dev: любой при
     `MATCH_AUTH_ALLOW_LEGACY_TOKENS=true`, например `match-gui`).
2. Клиент: `apps\desktop` → `pnpm tauri dev` (или релизная сборка с коммитом `7ad9c13`
   и позже). Вкладка **«Эмулятор и тесты»** — между «Журнал» и «Админ».

## Шаги

1. **Рендер**: вкладка «Эмулятор и тесты» → виртуальный смартфон отрисован
   (canvas). Переключить Портрет/Альбом, разрешение 360×640 / 390×844 / 412×915,
   масштаб 0.5–2×. Ожидание: рамка телефона меняет пропорции, контент не «плывёт».
2. **Ручная отправка кадра**: выбрать диалог (вкладка «Знакомства» → создать разговор,
   вернуться) → «Снять кадр и отправить наблюдение». Ожидание: бейдж
   `analysis_pending` (LLM=echo, vision-провайдер недоступен — корректно) и/или
   `analyzed` если vision-провайдер настроен; sha256 и размеры кадра отображаются.
3. **Сценарий**: выбрать сценарий в выпадающем списке → «Запустить сценарий».
   Ожидание: статус «Выполняется» → «Завершён»; в таблице результатов у каждого шага
   заполнены «Ожидалось / Факт / HTTP / Время / Итог». **Все строки — ok.**
4. **Пауза/сброс**: на любом сценарии «Пауза» (статус «Пауза», шаги стоят),
   «Продолжить» (доходит до «Завершён»); «Сбросить» посреди прогона — статус «Готов».
5. **Повтор**: «Повторить сценарий» (кнопка появляется при провалах) — после сброса
   состояние чистое; повторный прогон реtry-сценария сохраняет `action_replayed`
   (200, то же действие).
6. **Live-панели**: во время/после прогона — «Действия агента» (статусы sent/pending/
   rejected), «Решения агента» (mode + rationale + причина эскалации), «Бюджет
   автономности» (global_paused меняется в сценарии лимитов), «Ошибки автономности».

## Что фиксировать

- Скриншоты: телефон (4 режима экрана), таблица результатов после каждого сценария
  (ожидаемо 8 скриншотов), live-панель после сценария 8.
- Лог: `Ctrl+Shift+I` → Console не должен содержать ошибок (кроме ожидаемых
  сетевых при остановленном API).
- Расхождение ожидание/факт — зафиксировать в acceptance-checklist §26.

## Приватность

Сценарии создают тестовые диалоги/сообщения у текущего пользователя. Для очистки:
«Приватность» → удаление данных (двухшаговое подтверждение) или
`POST /api/v1/privacy/deletion-request`. Кадры не сохраняются (метаданные + sha256,
ADR-0007/0008); `source_label=emulator` отличает наблюдения лаборатории.

## Типичные провалы и что они значат

| Факт в таблице | Значение |
|---|---|
| `analysis_pending=true` | vision-провайдер недоступен/троттлинг — корректно (не «зелёный» успех) |
| `HTTP 401` | нет/неверный токен в настройках |
| `HTTP 404 conversation` | выбран диалог не из lab (seed создаёт свои диалоги сам) |
| `rate-limited 429` | прод-лимит 60/мин — повторить позже |
| `FAIL` при pause | сценарий запущен повторно без «Сбросить» — reset + run |
