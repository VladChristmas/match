## Компоненты

### Match Desktop (Tauri + React + TS)
- UI и управление знакомствами/диалогами.
- Настройки психопрофиля, разрешений и автономности.
- Импорт разрешённого контекста (manual-import).
- **Vision-слой:** наблюдение за экраном (средствами ОС), без парсинга DOM и без сетевых обращений к площадке.
- Локальный журнал действий, безопасное локальное хранилище.

### Match Agent Runtime
- Центральный контроллер: очередь событий, планировщик, тайм-ауты, retry, идемпотентность.
- Все действия проходят через **policy-engine** и проверку разрешений.
- LLM не выполняет действия напрямую.

### Модули (modules/*)
- `psychology` — наблюдения/гипотезы с источником, датой, уверенностью; **только для пользователя**.
- `dialogue` — контекст, стратегия, генерация и проверка ответа **в стиле пользователя**.
- `trust` — сигналы риска и мошенничества (объяснимые).
- `compatibility` — совместимость, взаимность, конфликты (раздельные показатели).
- `memory`, `audit-log`.

### LLM Gateway
- Единый интерфейс: облачные free LLM + локальный Ollama fallback.
- Версионирование промптов, структурированные ответы, лимиты, учёт токенов.
- Входящие сообщения = недоверенный ввод; отделение «анализа текста» от «разрешения на действие».

### Data Layer
- PostgreSQL для структурированных данных; локальное хранилище на клиенте.
- Персональные данные не собираются; доступ по токенам; изоляция по пользователю.

## Поток действия (упрощённо)

1. Vision-слой фиксирует экран → текст диалога (локально, минимизация).
2. `dialogue` строит контекст → `llm-gateway` формирует черновик.
3. `trust`/`compatibility`/`psychology` дают оценки и предупреждения.
4. `policy-engine` определяет уровень (A/B/C) → действие или передача пользователю.
5. Пользователь подтверждает отправку (на текущем этапе — вручную).
